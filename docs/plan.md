# Project Plan  
Retro Game Archive  

## Overview

This project plan outlines how I approached building the Retro Game Archive website. I used concepts from Chapter 4 of *Project Management for the Unofficial Project Manager* to think through risks ahead of time and break the project into manageable steps. Instead of just building the site and hoping everything worked, I tried to plan it intentionally.

---

# Risk Analysis (TAME Framework)

To evaluate risks, I used:

Impact (1–5)  
Probability (1–5)  
Risk Score = Impact × Probability  

I then applied the TAME framework (Transfer, Avoid, Mitigate, Eliminate) to decide how I would respond.

---

## Risk 1: Layout Issues on Different Devices

- **Description:** The layout might look good on my deskstop, but break on smaller screens.
- **Impact:** 3/5  
- **Probability:** 3/5  
- **Risk Score:** 9  
- **TAME Strategy:** Mitigate  

**Plan:**  
Use responsive CSS (grid layout, flexible image sizes) and test the website in different browser window sizes before submitting.

---

## Risk 2: Broken Links or File Path Errors

- **Description:** Navigation links or image paths might not work once the site is live on GitHub Pages.
- **Impact:** 4/5  
- **Probability:** 2/5  
- **Risk Score:** 8  
- **TAME Strategy:** Avoid  

**Plan:**  
Keep all main website files in the root directory, double-check relative paths, and test every link after deployment.

---

## Risk 3: Running Out of Time

- **Description:** Since this is the final week, there’s a risk of running out of time before everything is fully complete.
- **Impact:** 5/5  
- **Probability:** 3/5  
- **Risk Score:** 15  
- **TAME Strategy:** Mitigate  

**Plan:**  
Finish the website structure first, then complete documentation early so there’s buffer time to fix issues before the course closes.

---

# Work Breakdown Structure (WBS)

To stay organized, I broke the project into four phases. I tried to follow it all, but along the way there was always something that would be different from the outcome expected. 

---

## Phase 1 – Planning

1. Choose project concept (Retro Game Archive)
2. Draft the Project Scope Statement
3. Identify deliverables and limits
4. Revise scope based on feedbackm (I submitted my assignment late and was unable to get peer feedback, I also included the feedback of Ms. Cheri Whalen.)

---

## Phase 2 – Website Development

1. Create index.html homepage
2. Create about.html page
3. Build style.css for consistent design
4. Add images and hoverable cards
5. Test layout and navigation

---

## Phase 3 – Documentation

1. Write README.md
2. Revise scope.md
3. Write plan.md
4. Write retrospective.md
5. Link documentation folder in README

---

## Phase 4 – Testing & Deployment

1. Upload all files to GitHub
2. Enable GitHub Pages
3. Test the live site
4. Fix broken links or layout issues
5. Final review using the rubric checklist

---

# Reflection on Planning

Breaking the project into phases made it feel less overwhelming. Instead of trying to do everything at once, I divided the work into phases and worked on it day by day. I planned as I imagined it and I was able to thorughly make it through.
